| External observations | [Original machine-readable public snapshot](https://github.com/huntingthereferent/autobots-assemble/blob/main/views/world-continuity/latest.json) | GitHub ↔ PyPI connection from declared URL metadata rule, plus USGS as a **separate, unjoined source**. |

The finite source and workstation are not joined in this *view* merely because a bridge implementation exists. Authentic run-bound evidence requires the native journal, original source-owner run and accepted witness. Equally, a successful GitHub–PyPI metadata match is not independently authenticated ownership, and co-occurring timestamps do not join USGS earthquake records to software.

## Rebuild

Only Python 3 standard library is required:

```sh
python3 -m unittest discover -s profile-evidence -p 'test_*.py' -v
python3 profile-evidence/build.py
# When online, fetch the two published source projections before rendering:
python3 profile-evidence/build.py --refresh
```

The `--refresh` command fetches exactly two **allowlisted public JSON files** from the research repository and validates their shape; it does not modify their source. If either source is missing, unparseable or inconsistent, the refresh fails rather than publishing invented numbers. The dated observation remains dated even if the renderer executes later.

A proposed [GitHub Actions job](../.github/workflows/profile-evidence.yml) checks the renderer and can periodically refresh the committed snapshot and SVG. The profile repo has no evidence that a workflow is running until a successful job and committed output are observed.

The current layout is deliberately modest. It is the start of rUv-style **source → validate → render → inspect**, not yet a full live mathematical proof explorer. Future source lanes should be added only with explicit source owners, accepted run evidence, and a schema that distinguishes *observed*, *unresolved* and *not checked*.
